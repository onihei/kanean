# e-Tax 連携 調査メモ（Web-API / データ形式）

> リポジトリ `etaxapi/` の調査結果。Phase 5（e-Tax電子提出）の設計前提。
> - `etaxapi/api/`（API I/F定義書 43本, xlsx）= **新Web-API `UF_API/v1`（REST / JSON, 参照系中心）** … §1〜5
> - `etaxapi/format/`（データ形式等仕様書 ほか）= **送信データのXML形式の正本** … §6

---

## 1. 基本仕様（共通）

| 項目 | 内容 |
|---|---|
| ベースURL | `https://api.e-tax.nta.go.jp/UF_API/v1/` |
| 本人用 / 税理士用 | パスが `/my/...`（本人）と関与先指定（税理士）で分かれる |
| 認証ヘッダ | `Authorization: Bearer <base64の引継ぎ情報>` ＋ `X-Etax-Api-Key: <UUID>` |
| レスポンス | JSON（XTX取得のみ `application/xtx`）。Status 200/400/401/403/404/500/503 |
| マスキング | 一部応答に `maskedProperties` でマスク項目名を返す |

## 2. APIの分類（43本）と用途

> **重要**: この API 群は **ほぼ全て「参照系（GET）」＋口座更新・メッセージ管理**。
> **申告データを送信（提出）するAPIは含まれていない。**

| 区分 | 主なAPI | 本システムでの用途 | 関連要件 |
|---|---|---|---|
| 受信通知・メッセージ | メッセージ一覧/参照/移動/削除/完全削除/復元、サブフォルダー一覧、フォルダパスワード認証 | **受信通知の取得・管理** | F-SUB-4 |
| 提出済データ取得 | XTX取得（`/my/originals/${手続ID}${受付番号}`）、受信データ参照 | 申告控え（XTX）保存・検証 | F-SUB-3/4 |
| 申告事項の参照（要約） | 所得税に関する事項参照（`/my/incomeTaxInfo`, 過去5年）、消費税に関する事項参照、法人税、消費税(法人) | 申告内容のサマリ確認・照合 | 補助 |
| 納付・還付 | ダイレクト納付口座 参照/更新、振替納税口座 参照、還付先口座 参照 | 納付/還付情報の取得・更新 | 納付 |
| 利用者情報 | 基本情報参照、利用者状態参照、利用者設定 参照/更新 | 連携前提情報 | F-AUTH補助 |
| その他 | NISA口座開設状況、贈与税関係送信事績取得、納税者リスト/関与先/委任先税理士一覧 | 対象外（個人事業の範囲外） | – |

### 参照系の応答プロパティ例（消費税に関する事項参照）
`consumptionTaxList[].taxYear / updateDate / kaniKazeiSeidoSentakuTeishutsuJokyo（簡易課税制度選択提出状況）/ kazeiJigyoshaSentakuTeishutsuJokyo（課税事業者選択）/ kazeiKikanTokureiSentakuTeishutsuJokyo（課税期間特例選択）/ kazeiUriagedaka（課税売上高）/ chukanNofuZeigaku（中間納付税額）/ chukanNofuJotowarigaku（中間納付譲渡割額）`

> これは申告データの**要約項目**であり、**申告書の全欄ではない**。帳票マッピングの正本にはならない（§4）。

## 3. 本システムでの活用方針

- **使える**: 受信通知/メッセージ処理（F-SUB-4）、XTX取得による控え保存・検証、納付情報、利用者状態の参照。Phase 5 の**提出後フロー**の実装I/Fとして直接利用可能。
- **補助的に使える**: 所得税/消費税の事項参照で、自システムの申告内容と e-Tax 側の状態を照合（簡易課税選択状況など）。

---

## 4. このAPI集ではカバーされない（Phase 5の別途課題）

| 不足項目 | 内容 | 対応 |
|---|---|---|
| 申告データの**送信（提出）** | 組成した XTX を提出するエンドポイントが本API集に無い | e-Tax の**送信系仕様**（受付システム外部インタフェース仕様書 等）を別途入手 |
| **XTX（XML）の組成** | 申告書の各欄→XML要素の対応（XML帳票仕様） | NTAの XML帳票仕様 / スキーマを入手し帳票マッピングに反映 |
| **電子署名（XMLDSig）・NFC** | マイナンバーカードによる署名、ICカードリーダ/スマホNFC | 別アプリ/ライブラリで実装（F-SUB-2） |

> → PRD のリスク R-2（e-Tax連携の難度）を裏付け。**Phase 3（PDF手動提出）を実用ゴール**に据える方針は妥当。

---

## 5. 帳票マッピングとの関係

- 帳票マッピングの**正本** = NTA の最新申告様式（確定申告書／青色申告決算書／消費税申告書(簡易)）＋ e-Tax の **XML帳票仕様（組成スキーマ）**。
- 本API群（参照系）は**補助**（提出済みデータの照合用）。
- 注意: **申告書A・Bは令和3年分から「確定申告書」に統合**。様式は最新版を基準にする。

## 6. データ形式等仕様書（`etaxapi/format/`）— XTX組成の正本

e-Tax 送信データ（XML）の形式を定義する公式仕様。**Phase 5 のXTX組成と帳票マッピングの正本**。

### 6.1 収録物
| ファイル | 内容 |
|---|---|
| データ形式等仕様書.docx | 本体（§1〜§5、約2,500段落） |
| 資料1_IT部要素一覧.xlsx | IT部（共通ヘッダ）の要素一覧（87行：税務署名/提出年月日/利用者識別番号 等） |
| 資料2_共通ボキャブラリ一覧.xlsx | 共通データ型（119行：name/address/kingaku 等の型定義・文字数・出現回数） |
| 資料3_汎用申請書.xlsx | 汎用申請書の様式構造 |
| 資料1_API一覧.xlsx | 受付APIのドメイン・URL許容一覧・メッセージコード |

### 6.2 送信データのXML構造（封筒）
```
<DATA id="DATA">
  <手続ID VR="1.0" id="手続ID">           ← 手続単位（pid属性で汎用手続も）
    <CATALOG id="CATALOG"> … </CATALOG>     管理用部分
    <CONTENTS id="CONTENTS">
       <IT VR="1.0" id="IT"> … </IT>        IT部（共通ヘッダ：資料1）
       <様式ID VR="1.0" page="1"> … </様式ID>  帳票面（様式ごと）
       <TENPU> … </TENPU>                   第三者作成添付書類
       <XBRL>/<XBRL2_1>                      XBRL部
       <SOFUSHO>/<ATTACH>/<CSV>              送付書・添付・CSV
    </CONTENTS>
  </手続ID>
  <dsig:Signature xmlns:dsig=".../xmldsig#"> … </dsig:Signature>   XML署名(XMLDSig)
</DATA>
```
> 1回の申告 = 1つのXMLデータ。署名は `dsig:Signature`（XMLDSig）で封筒末尾に付与（F-SUB-2）。

### 6.3 本体の構成（§1〜§5）
| 章 | 内容 | 我々での用途 |
|---|---|---|
| §1 XML構造 | 上記封筒・送信データ単位 | XTX組成の骨格 |
| §2 共通ボキャブラリ/属性/RDF/XBRL | データ型・属性・XBRL(2.0/2.1) | 各項目の型・桁・形式 |
| §3 XML構造設計書（帳票） | 帳票XMLの定義 | 様式の構造 |
| §4 帳票フィールド仕様書 | 各項目の入力型（文字型/数値型 等3種）・桁・値範囲・**自動計算方法** | 入力チェック・計算の正解 |
| §5 **帳票間連動仕様書** | **転記元→転記先**（帳票名・様式ID・帳票項番・**タグ名**）の対応 | **決算書→申告書の転記マッピングの正本** |

### 6.4 重要な切り分け（まだ不足するもの）
この仕様書は **共通の枠組み（封筒・共通ボキャブラリ・IT部・連動ルールの定義方法）** を定める。
**我々の対象3帳票の「様式ID＋各項番→タグ名」の個別定義（様式別の帳票フィールド/連動の実データ）** は、
e-Tax仕様公開ページの**様式別（手続別）の仕様**として別ファイルにある。Phase 5 のXML層には以下が追加で必要:

| 必要なもの | 対象 |
|---|---|
| 確定申告書（所得税）の様式仕様 | 様式ID・帳票項番・タグ名 |
| 所得税青色申告決算書（一般用）の様式仕様 | 同上 |
| 消費税及び地方消費税申告書（簡易課税用）の様式仕様 | 同上 |
| 送信系の手続仕様（提出エンドポイント） | §4で既述の不足（受付システム送信） |

### 6.5 帳票マッピング仕様への含意
- `statement_line_code` を **2層の宛先**を持てる設計にする:
  - **PDF層（Phase 3）**: NTA様式の表示行
  - **XML層（Phase 5）**: e-Tax 様式ID + タグ名（§5の連動・§4のフィールドに対応）
- 我々のデータモデルの「控除前所得金額の連結」「決算書→申告書の転記」は、§5 帳票間連動が定義する **転記元→転記先** と概念一致。
