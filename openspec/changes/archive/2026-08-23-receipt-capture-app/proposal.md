## Why

現金取引はレシートが唯一のソースであり、撮り逃すと帳簿に残らない。一方カード払いのレシートは
[[acquisition]] が明細を取り込むため、そのまま起票すると**二重計上の種**になる。この分岐は
「撮影の瞬間」にしか安く取れない情報で、後から画像だけを見て判別するのは高い。

また飲食費の交際費／会議費判定は 1 人あたり金額と参加者記録が要件であり、これも撮影時にしか取れない。

スマホは会計データを見る「クライアント」ではなく**キャプチャデバイス**であり、本体と直接通信する
必要がない。既存の不変条件（TCP を開かない・LAN 直結をしない）を一切崩さずに、
クラウドのファイル往復だけで搬送できる。（探索の正 = Issue #112）

## What Changes

- **モバイルアプリ（Flutter）を新設する**。同一リポジトリのルート直下 `mobile/`。アプリ ID
  `com.susipero.kanean.mobile`。**無料のコンパニオンアプリ**として配る
- 撮影 → 端末内の簡易検査（ブレ／白飛び／傾き検出・オンデバイス OCR による日付と金額の目視確認）
  → **現金／カードのワンタップ分岐** → 画像とメタ JSON をクラウドの inbox へ書く
- Mac 側は **MCP の定型手順「レシートの取込」**として提供する。Claude Desktop が inbox の画像を読み、
  MCP 経由で本体へ登録する。**利用者に別途スキルを導入させない**（[[mcp-server]] の既存規約）
- 現金は draft 仕訳＋証憑添付を作る。**カード払いは新規起票せず**、既存明細と突合して証憑としてのみ添付する
- 登録と添付保存の完了を **status ファイル**で端末へ返し、**それを確認してから**クラウド上の中継コピーを削除する
- アプリは端末内 SQLite に送信キューと読み取り履歴を持ち、履歴に「✓ 登録済み」を表示する
- 搬送層は最初から抽象化する（iOS = iCloud Documents コンテナ、Android = 同型のアプリ専用フォルダ）

**非ゴール**（いずれも Issue #112 で確定済み）

- LAN 直結（スマホ→Mac の直接通信）。[[local-access]] の SHALL と正面衝突する
- 会計データの参照・閲覧
- エクスポート機能・単体アプリとしての完結性。Kanean 専用のコンパニオンに絞る
- マイナンバーカードの NFC 読み取り／JPKI 署名。スマホに署名させて本体が送る経路は制度的に閉じており、
  自前送信をやるなら Mac 直結の IC カードリーダが正解でスマホは要らない

## Capabilities

### New Capabilities

- `receipt-capture`: 端末側の振る舞い。撮影と簡易検査、現金／カードその他の文脈付与、
  オフラインキューと再送、読み取り履歴と登録状態の表示、端末に会計データを持たないこと
- `receipt-inbox`: 端末と Mac をつなぐ**ファイル契約**。inbox のレイアウト、画像に添えるメタ JSON の
  スキーマ、status ファイルによる逆方向の応答、中継コピーを消してよい条件、再試行時の冪等性

（[[acquisition]]（取得の振る舞い）と [[skill-import]]（投入の契約）が分かれているのと同じ分割）

### Modified Capabilities

- `skill-import`: レシート由来の投入契約を追加する。現金レシートの draft 投入（画像の SHA-256 による冪等性）と、
  カード払いレシートの**突合候補の提示**（新規起票をしない経路）
- `mcp-server`: 定型手順に「レシートの取込」を追加し、その手順が [[receipt-inbox]] の規約
  （現金／カードの振り分け・削除は登録完了の確認後）を運ぶことを要求する

## Impact

- **新規**: `mobile/`（Flutter + Riverpod + 端末内 SQLite）。pnpm workspace は `packages/*` のみなので
  pnpm・turbo からは不可視。eslint の `ignores` に `mobile/**` を追加。CI は Flutter SDK + Xcode の別ワークフロー
- **`packages/shared`**: メタ JSON と status ファイルの **JSON Schema を 1 本**置く。TS 側はそれで検証し、
  Dart 側も同じスキーマから検証する。**同じゴールデンフィクスチャで両側をテスト**して契約のドリフトを防ぐ
- **`packages/server`**: `/skill/receipts/*` の追加（[[skill-import]] の既存の検証・期間ゲート・
  科目解決の権威をそのまま通す）
- **`packages/mcp`**: 定型手順「レシートの取込」の追加
- **既存の [[attachments]] は変更しない**。HEIC 受理と SHA-256 記録は既にあり、そのまま使う
- 画像は Claude（Anthropic）へ送られる。取引先・金額・位置情報を含むため、方針として明示する
  （アプリが LLM を呼ばず利用者の Claude サブスクで動かす既存方針とは整合）
- 名称は [[Issue #292]] の Kanean 改名に従う。本 change は改名の完了を前提としない（識別子は
  `com.susipero.kanean.mobile` で確定済み）
