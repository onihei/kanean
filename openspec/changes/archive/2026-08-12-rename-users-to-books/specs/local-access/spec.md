## MODIFIED Requirements

### Requirement: 取込スキルの呼び出し境界

システムは `/skill` 配下のルートを、ループバック到達性のみを条件として受け付ける SHALL。
トークンその他の認証情報を要求してはならない。対象帳簿の解決は [[books]] の規約に従う。

#### Scenario: ローカルのスキルが認証なしで呼ぶ

- **WHEN** 同一マシンで動作する取込スキルが `http://127.0.0.1:<port>/skill/*` を呼ぶ
- **THEN** 解決した帳簿の data plane に対して処理し、認証情報を要求しない

#### Scenario: 過大なリクエストを遮断する

- **WHEN** 5MB を超えるリクエストボディが `/skill/*` に到達する
- **THEN** 413 を返す

### Requirement: シード追加への自己修復

システムは data plane を開くたびに冪等なシード適用を行い、後から追加された標準シードへ追いつかせる SHALL。

#### Scenario: 開くたびに不足シードを補う

- **WHEN** `DbRouter.bookDb()` が既存の data plane を開く
- **THEN** 不足している `is_system` シードを冪等に投入する
- **AND** 利用者側の操作を一切要求しない

## REMOVED Requirements

### Requirement: 単一オーナーの自動解決

**Reason**: 「オーナー（ユーザー）を1人だけ解決する」という前提を撤回する。分離の単位は
利用者ではなく**帳簿**であり、税理士が顧問先の帳簿を N 冊持つ運用では2冊以上が正常な状態になる。
2行以上で起動を中断する要件も、その前提が消えるため成立しない。

**Migration**: [[books]] の「帳簿の一覧と作成」「対象帳簿の解決」が置き換える。
初回起動で1冊自動作成する挙動と、data plane の初期化・シード投入は同等の保証として残る。
`GET /api/me` は廃止し `GET /api/books` に置き換える。
