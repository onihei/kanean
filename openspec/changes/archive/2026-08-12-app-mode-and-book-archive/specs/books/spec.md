## ADDED Requirements

### Requirement: 帳簿のアーカイブ

システムは帳簿を**アーカイブ**して一覧から下げられる SHALL。アーカイブは control plane の状態変更のみであり、
data plane のファイル（`$DATA_DIR/books/{id}.sqlite`・証憑ディレクトリ）には触れない。
顧問契約の終了・使わなくなった帳簿の整理に用いる。削除は引き続き提供しない。

#### Scenario: 帳簿をアーカイブする

- **WHEN** `POST /api/books/:id/archive` を呼ぶ
- **THEN** 当該帳簿を `archived` にし、既定の一覧から外す
- **AND** data plane のファイルは削除も改名もしない

#### Scenario: アーカイブを復帰する

- **WHEN** `POST /api/books/:id/unarchive` を呼ぶ
- **THEN** 当該帳簿を `active` に戻し、既定の一覧に再び現れる

#### Scenario: アーカイブ済み帳簿は読めるが書けない

- **WHEN** アーカイブ済みの帳簿を `X-Book-Id` または `?bookId=` で明示指定して参照する
- **THEN** 参照系（帳票・元帳・エクスポート）は成功する
- **AND** 更新系（起票・確定・取込・マスタ更新）は 409 を返し、いずれのデータも変更しない

#### Scenario: 最後のアクティブ帳簿はアーカイブできない

- **WHEN** アクティブな帳簿が1冊しかない状態でその帳簿をアーカイブしようとする
- **THEN** 409 を返して拒否する（アクティブ0冊は起動時の自動作成を誘発し、空の帳簿が生まれるため）

#### Scenario: アーカイブは会計データを変えない

- **WHEN** 帳簿をアーカイブして復帰する
- **THEN** 仕訳・残高・帳票の内容はアーカイブ前と一致する

## MODIFIED Requirements

### Requirement: 帳簿の一覧と作成

システムは帳簿の一覧を返し、新しい帳簿を作成できる SHALL。作成時に data plane を初期化する。
一覧の既定はアクティブな帳簿のみとし、アーカイブ済みを含めるかは呼び出し側が明示する。

#### Scenario: 帳簿を一覧する

- **WHEN** `GET /api/books` を呼ぶ
- **THEN** アクティブな帳簿のみについて `id`・`name`・`createdAt`・アーカイブ状態を返す

#### Scenario: アーカイブ済みを含めて一覧する

- **WHEN** `GET /api/books?includeArchived=true` を呼ぶ
- **THEN** アーカイブ済みを含む全帳簿を、アーカイブ状態が区別できる形で返す

#### Scenario: 帳簿を作成する

- **WHEN** `POST /api/books` に `name` を送る
- **THEN** ULID を採番して `books` に行を作成する
- **AND** `$DATA_DIR/books/{id}.sqlite` を作成し、最新スキーマへマイグレーションして標準シードを投入する
- **AND** 作成した帳簿の `id` と `name` を返す

#### Scenario: 起動時に最初の帳簿を用意する

- **WHEN** アクティブな帳簿が1冊も無い状態でサーバが起動する
- **THEN** `マイ帳簿` という名前の帳簿を1冊作成し、その data plane を初期化する

#### Scenario: 帳簿を改名する

- **WHEN** `PATCH /api/books/:id` に `name` を送る
- **THEN** 当該帳簿の `name` を更新する
- **AND** data plane のファイル名は変更しない（id とファイル名は不変）

#### Scenario: 帳簿の削除は提供しない

- **WHEN** 帳簿を削除する API を探す
- **THEN** そのようなエンドポイントは存在しない（税務データの消失は不可逆なため、ファイルの手動削除に委ねる）

### Requirement: 対象帳簿の解決

システムは各リクエストの対象帳簿を、ヘッダ・クエリ・暗黙の順で解決する SHALL。
いずれでも一意に定まらない場合は、推測せずエラーとする。
暗黙解決の判定は**アクティブな帳簿の冊数**に基づく（アーカイブ済みは選択候補に含めない）。

#### Scenario: ヘッダで指定する

- **WHEN** `X-Book-Id` ヘッダを伴うリクエストが到達する
- **THEN** その帳簿の data plane に対して処理する

#### Scenario: クエリで指定する

- **WHEN** `X-Book-Id` が無く `?bookId=` が指定されている
- **THEN** その帳簿の data plane に対して処理する
- **AND** これによりブラウザネイティブの GET（エクスポート zip・証憑ダウンロード）も帳簿を指定できる

#### Scenario: アクティブが1冊しか無ければ指定を省略できる

- **WHEN** ヘッダもクエリも無く、アクティブな帳簿が1冊しか存在しない
- **THEN** その帳簿を対象として処理する
- **AND** アーカイブ済みの帳簿が何冊あっても判定には影響しない

#### Scenario: 曖昧なら拒否する

- **WHEN** ヘッダもクエリも無く、アクティブな帳簿が2冊以上存在する
- **THEN** 400 を返し、いずれの帳簿にも書き込まない
- **AND** 応答に選択可能な（アクティブな）帳簿の `id` と `name` を含める（呼び出し側が人へ提示できるようにする）

#### Scenario: 存在しない帳簿を指定する

- **WHEN** `books` に存在しない id を指定する
- **THEN** 404 を返す
