  - **原因は Electron の既知バグ**（[electron#34762](https://github.com/electron/electron/issues/34762)・
    [#30201](https://github.com/electron/electron/issues/30201)・2022年から open）。
    Electron は `setUserAgent()` で **UA 文字列しか変えず** User-Agent Client Hints のメタデータを
    更新しない。さらに高エントロピーのヒント（`sec-ch-ua-full-version-list` 等）は `Accept-CH` で
    要求されても一切返さない。結果、3.7 の UA 正規化と噛み合って**不整合**が残る:
    | | 殻A（実 Chrome） | 殻B（Electron・補正前） |
    |---|---|---|
    | UA 文字列 | `Chrome/151.0.0.0` | `Chrome/150.0.7871.224` |
    | `userAgentData.brands` | `Not=A?Brand` / **`Google Chrome`** / `Chromium` | `Not;A=Brand` / `Chromium` |
    「UA は Chrome と名乗るのにブランドに Chrome が無い」＝機微な書類を出し渋られる
  - 対処: `applyClientHints()` で CDP `Emulation.setUserAgentOverride` に `userAgentMetadata` を
    添え、**アプリが既に名乗っている UA と辻褄を合わせる**（新たに素性を偽るのではなく、
    Electron のバグで答えられていない標準の問い合わせに答える）
  - ⚠ **遷移前のウィンドウでは `sendCommand` が解決しない**（実測: 15秒待っても返らない）。
    ただし指定自体は効く。`await` したままだと巡回が止まるので待ちを打ち切る（`CDP_SEND_TIMEOUT_MS`）
  - 結果: **0/22 → 20/22 → 22/22**。補正直後の回は2注文（2026-05-20 の1行注文）が残ったが、
    **同じ範囲で回し直したら再現せず 22/22**。殻A と `acq-diff` で完全一致（56明細行）。
    残った2件は補正前に劣化していたセッションの後を引いたもので、恒常的な欠陥ではなかった
  - ⚠ 検証の限界: 補正を当てた回は Client Hints の補正と**Amazon への入り直しが同時**に起きている。
    寄与を厳密には分離できていない（ただし補正前は入り直し直後でも最良 14/22 だった）
  - **否定された仮説**（記録として残す。同じ道を二度通らないため）:
    - 「叩きすぎ／レート制限」… 殻B を5回回した**後**に殻A を回しても 22/22。絞り込みなら殻Aも落ちる
    - 「`scrollIntoView` の競合」… `behavior:'instant'` を明示しても 0/22 のままで**効かなかった**。
      競合自体は実在する危険なので修正とテストは残したが、この症状の原因ではない
