# desktop-app Specification

## Purpose

Kanean をデスクトップアプリとして起動・終了・配布するための振る舞いを定める。
ターミナルを介さず起動でき、アプリを終了したあとにプロセス・リスナー・一時ファイルの
いずれも残さないことを保証する。アクセス境界そのものの規約は [[local-access]] が持つ。
（[docs/architecture.md] §12）

## Requirements

### Requirement: ターミナルを介さない起動

システムはアプリケーションアイコンの起動操作のみで、会計データを操作できる状態に到達する SHALL。
利用者にコマンド実行・ポート指定・サーバの事前起動を要求してはならない。

#### Scenario: アイコンから起動して帳簿を開く

- **WHEN** 利用者がアプリケーションアイコンを起動する
- **THEN** ウィンドウが開き、帳簿の一覧・仕訳・帳票を操作できる状態になる
- **AND** 利用者はコマンドを一切実行していない

#### Scenario: 起動前にサーバを立てる必要がない

- **WHEN** アプリ起動前に Kanean のプロセスが1つも動いていない
- **THEN** 起動操作だけで会計データにアクセスできる

### Requirement: アプリ寿命に閉じたプロセス

システムは会計データを扱うプロセスをアプリケーション本体の寿命に一致させる SHALL。
アプリ終了後に、会計データへ到達しうるプロセス・リスナー・待ち受けを残してはならない。

#### Scenario: 終了で待ち受けが消える

- **WHEN** 利用者がアプリケーションを終了する
- **THEN** ローカル連携用の待ち受け（[[local-access]]）は消滅し、以後いかなる経路からも会計データへ到達できない

#### Scenario: 終了後にプロセスが残らない

- **WHEN** アプリケーションを終了する
- **THEN** Kanean に属するプロセスは1つも残らない

#### Scenario: ウィンドウを閉じると終了する

- **WHEN** 利用者が最後のウィンドウを閉じる
- **THEN** アプリケーションは終了し、ウィンドウの無いまま常駐する状態にならない

#### Scenario: 自動起動しない

- **WHEN** 利用者がマシンにログインする
- **THEN** Kanean は起動しない（常駐サービスとして登録されない）

#### Scenario: 二重起動しない

- **WHEN** 既に起動している状態でアイコンを再度起動する
- **THEN** 新しいプロセスを作らず、既存のウィンドウを前面に出す

### Requirement: UI へのアプリ内配信

システムは UI と業務 API を、外部から到達可能な待ち受けを開くことなくアプリ内部で配信する SHALL。
UI 経路のために TCP ポートを開いてはならない。

#### Scenario: UI が TCP を使わずに API を呼ぶ

- **WHEN** UI が仕訳・帳票・マスタなどの業務 API を呼ぶ
- **THEN** リクエストはアプリ内部で処理され、TCP による待ち受けを経由しない

#### Scenario: UI 経路のポートが存在しない

- **WHEN** アプリ起動中にマシンの待ち受けポートを列挙する
- **THEN** Kanean の UI 経路に対応する待ち受けポートは存在しない

### Requirement: ダウンロードと別窓表示の維持

システムはアプリ内配信に切り替えたあとも、ファイルの保存・別窓表示の振る舞いを維持する SHALL。
とくに大きな成果物をメモリ上に全展開してはならない。

#### Scenario: エクスポート zip を保存する

- **WHEN** 利用者が設定画面からフルデータエクスポートを実行する（[[data-ops]]）
- **THEN** ファイル名付きで保存でき、zip 全体をメモリ上に展開せずに書き出される

#### Scenario: 帳票 CSV・様式 PDF を保存する

- **WHEN** 利用者が帳票 CSV または様式 PDF のダウンロードを実行する
- **THEN** ファイル名付きで保存され、Shift_JIS 変換で欠落した文字の警告も従来どおり提示される

#### Scenario: 証憑を別窓で表示する

- **WHEN** 利用者が仕訳に添付された証憑を開く
- **THEN** 証憑が別窓で表示される

#### Scenario: 様式 PDF をプレビューする

- **WHEN** 利用者が決算書・確定申告書・消費税申告書の様式 PDF プレビューを開く
- **THEN** 官製様式が全ページ描画される（フォント・画像の脱落がない）

### Requirement: 該当画面を開く外部リンク

システムは自身を `kanean://` スキームの取り扱い先として登録し、外部から渡されたリンクで
**アプリを前面に出して該当画面を表示する** SHALL。リンクの受理はアプリ内の画面遷移に限り、
会計データの変更を伴う操作をリンクだけで実行してはならない。

#### Scenario: 起動中にリンクを開く

- **WHEN** アプリが起動している状態で `kanean://` のリンクが開かれる
- **THEN** ウィンドウが前面に出て、リンクが指す画面が表示される

#### Scenario: 未起動でリンクを開く

- **WHEN** アプリが起動していない状態で `kanean://` のリンクが開かれる
- **THEN** アプリが起動し、リンクが指す画面が表示される

#### Scenario: リンクだけで会計データが変わらない

- **WHEN** 変更操作を示唆するリンクが開かれる
- **THEN** 該当画面を開くにとどまり、利用者の操作なしに会計データは変更されない

#### Scenario: 解釈できないリンクで壊れない

- **WHEN** 未知の経路を指す `kanean://` のリンクが開かれる
- **THEN** アプリは通常の初期画面を表示し、異常終了しない

### Requirement: 配布物の成立

システムは受け取った利用者が追加のランタイム導入なしにインストール・起動できる配布物を提供する SHALL。
配布物には MCP クライアントへ導入するためのバンドル（[[mcp-server]]）を同梱し、
利用者が別途取得する必要がない状態にする。

#### Scenario: 受け取った人が起動できる

- **WHEN** 配布物を受け取った利用者が、Node.js も pnpm も導入していないマシンにインストールする
- **THEN** アプリが起動し、帳簿を作成して仕訳を入力できる

#### Scenario: 署名の警告が出ない

- **WHEN** 配布物を初めて開く
- **THEN** 開発元を検証できない旨の警告なしに起動できる

#### Scenario: MCP バンドルを同梱している

- **WHEN** 配布物からインストールしたアプリで連携の導線を実行する
- **THEN** ネットワークから何も取得することなく、導入用のバンドルが得られる
