# filing Specification

## Purpose

申告の提出を支援する。confirmed 仕訳と既存の申告書組成（[[tax-return]]）を入力源に、
申告前チェック・確定申告書等作成コーナー向けの入力指示書・転記手順の規約・申告の完了記録を提供する。
数字の正は core、送信と認証は人間に残し、システムも AI も「提出可能」を宣言しない（`legalRisk:high`）。
作成コーナーとの欄対応は [docs/filing-corner-mapping.md] を正とする。
e-Tax フル API 送信・xtx 書き出し・eLTAX は本 capability のスコープ外（将来拡張）。

## Requirements

### Requirement: 申告前チェック

システムは申告の前提が満たされているかを決定的に判定し、不備（blocking）と注意（warning）に
区分して返す SHALL。判定は confirmed 仕訳と保存済み設定のみを入力源とし、同じ帳簿状態に対して
常に同じ結果を返す。

#### Scenario: 前提の不備を区分して返す

- **WHEN** `GET /api/filing/precheck` を呼ぶ
- **THEN** 少なくとも次の観点を判定して返す: 貸借の一致、青色申告特別控除の設定、
  消費税の事業区分の設定、所得控除入力の保存有無、未確定 draft の件数
- **AND** 各項目は不備（申告値が組めない/明らかに誤る）か注意（確認を促す）かに区分され、
  該当画面への導線を伴う

#### Scenario: 未確定 draft を黙って落とさない

- **WHEN** 承認待ちの draft 仕訳が存在する状態で precheck を呼ぶ
- **THEN** 集計には含めないまま、件数を注意として明示する

#### Scenario: 会計年度が無い場合

- **WHEN** open な会計年度が存在しない
- **THEN** 200 で `precheck: null` を返し、年度作成への導線を示す

#### Scenario: 提出可能を宣言しない

- **WHEN** すべての観点で不備が見つからない
- **THEN** 「不備が見つからなかった」とのみ返し、「提出可能」という判定は返さない

### Requirement: 入力指示書の生成

システムは確定申告書等作成コーナーへ転記すべき値の一覧（入力指示書）を、作成コーナーの
画面の順序で生成する SHALL。転記値はすべて [[tax-return]] と同一の組成から導出し、
指示書のために新たな計算を持ち込まない。

#### Scenario: 画面順の転記項目を返す

- **WHEN** `GET /api/filing/instruction-sheet` を呼ぶ
- **THEN** 青色申告決算書・所得税（第一表・第二表）・消費税（簡易課税）の各画面グループごとに、
  画面名・欄ラベル・転記値の並びを返す
- **AND** 欄対応は [docs/filing-corner-mapping.md] に従う

#### Scenario: 検算用の税額を含める

- **WHEN** 入力指示書を取得する
- **THEN** 作成コーナーの最終画面と突き合わせるための検算ブロック
  （所得税の申告納税額または還付額・消費税の納付税額［国・地方・合計］）を含む

#### Scenario: 申告書 PDF と金額が一致する

- **WHEN** 同一年度で入力指示書と申告書組成（[[tax-return]]）を取得する
- **THEN** 同じ組成関数を用いるため対応する金額は一致する

#### Scenario: 会計年度が無い場合

- **WHEN** open な会計年度が存在しない
- **THEN** 200 で `sheet: null` を返し、前提の導線を示す

### Requirement: 転記手順の規約

システムが配布する転記手順（[[mcp-server]] の定型手順として提供）は、AI による転記を
入力指示書の写字に限定し、認証と送信を利用者に残す SHALL。

#### Scenario: 転記値は指示書のみを源とする

- **WHEN** 手順に従って AI が作成コーナーへ入力する
- **THEN** 入力する数値・選択はすべて入力指示書に由来し、AI が計算・推測・補完した値を入力しない
- **AND** 指示書に無い入力を求められた場合は利用者に確認する

#### Scenario: 認証と送信は利用者が行う

- **WHEN** 手順がログイン・マイナンバーカードの認証（QR 読み取り等）・送信操作に到達する
- **THEN** 手順はそこで利用者に操作を委ね、AI が認証情報を扱わず送信も行わない

#### Scenario: 検算の一致を送信前に確認する

- **WHEN** 作成コーナーが最終的な税額を表示する
- **THEN** 手順は指示書の検算ブロックとの一致を確認して利用者に提示し、
  一致した場合のみ送信（利用者の操作）へ進む

#### Scenario: 検算が一致しない場合は進めない

- **WHEN** 作成コーナーの税額と検算ブロックが一致しない
- **THEN** 手順は送信へ進めず、どの値が食い違ったかを利用者に報告する
- **AND** 完了記録は作成しない

### Requirement: 申告の完了記録

システムは申告の提出を年分ごとに記録し、受信通知・申告書控え等を証憑として保存できる SHALL。
記録は事実の記録であり、システムが提出の有効性を判定・宣言するものではない。

#### Scenario: 完了を記録する

- **WHEN** `POST /api/filing/records` に税目（所得税/消費税）・提出方法・提出日・
  受付番号（任意）・メモ（任意）を送る
- **THEN** open な会計年度（＝年分）の完了記録として保存して返す

#### Scenario: 同一年分に複数の記録を持てる

- **WHEN** 同じ年分に税目違いや再提出（訂正・修正）の記録を追加する
- **THEN** 既存の記録を上書きせず、別の記録として保持する

#### Scenario: 控えを証憑として添付する

- **WHEN** `POST /api/filing/records/:id/attachments?fileName=...` に控え PDF 等を送る
- **THEN** [[attachments]] と同じ形式・サイズ制約・保存規約（帳簿ごとのディレクトリ・
  メタとハッシュの記録）で保存する

#### Scenario: 記録を参照・削除できる

- **WHEN** `GET /api/filing/records?year=` / `DELETE /api/filing/records/:id` を呼ぶ
- **THEN** 年分の記録（添付メタ含む）を一覧でき、誤登録は添付ごと削除できる
