# web-app Specification

## Purpose

React + Vite の SPA（`packages/web`）が提供する画面体験。サイドナビによる業務メニュー、
ホームのダッシュボード（KPI・月次収支・納税予測 what-if）、初回セットアップ導線、
取込レビューの例外ベース UI、設定画面（マスタ・データ管理）を担う。
サーバ API（`/api`）を `@kanean/shared` の型経由で呼び、会計計算そのものは持たない。
（[docs/architecture.md] §2/§12・[docs/roadmap.md] Phase 5 slice11）

## Requirements

### Requirement: 業務メニューのナビゲーション

システムは業務フローに沿ってグルーピングしたサイドナビを提供する SHALL。
ログイン画面・ログアウト操作は持たない（アプリを開くと直ちに業務画面が表示される）。
サイドナビには現在開いている帳簿を表示する。帳簿の切替と作成の導線はアプリモードに応じて露出を変える。

#### Scenario: 業務グループで画面を辿る

- **WHEN** 利用者がサイドナビを開く
- **THEN** 「自動で仕訳（連携サービス・取込明細・残高突合・名寄せ）」「手動で仕訳」「会計帳簿」「集計・レポート」「決算・申告」「各種設定」のグループで画面を選択できる

#### Scenario: ログインを求めずに起動する

- **WHEN** 利用者がアプリを開く
- **THEN** 認証情報の入力を求めず、直接業務画面（モード未設定ならモード選択、会計年度未設定なら初回セットアップ）を表示する

#### Scenario: 開いている帳簿を示す

- **WHEN** 利用者がサイドナビを見る
- **THEN** 現在対象になっている帳簿の名前を表示する

#### Scenario: 事務所モードで帳簿を切り替える

- **WHEN** モードが `office` で、利用者がサイドナビから別の帳簿を選ぶ
- **THEN** 帳簿選択画面を経て切り替え、以降のすべての API 呼び出しがその帳簿を対象とする
- **AND** 次回起動時にはその帳簿を自動では開かず、帳簿選択画面でハイライトするに留める

#### Scenario: じぶんの帳簿モードでは切替を見せない

- **WHEN** モードが `personal` で利用者がサイドナビを見る
- **THEN** 帳簿の切替・作成の導線を表示しない（アクティブな帳簿は常に1冊のため）

#### Scenario: SPA を直接 URL で開く

- **WHEN** 本番配信で未知のパスに GET する
- **THEN** SPA の index.html を返す
- **AND** `/api` `/skill` で始まるパスは HTML を返さず 404 JSON を返す（デプロイずれを観測可能にする）

### Requirement: URL がナビ状態の真実源である

システムは画面の場所（タブ・開いている元帳・補助元帳・設定セクション）を URL のハッシュに持ち、
URL からその画面を復元できる SHALL。ハッシュは `#<tab>`・`#<tab>/ledger/<accountId>`・
`#<tab>/ledger/<accountId>/sub/<subAccountId>`・`#settings/<section>` の形をとる。

#### Scenario: ブラウザバックで前の画面に戻る

- **WHEN** 画面を遷移した後にブラウザの「戻る」を使う
- **THEN** 直前の画面（タブ・元帳・設定セクション）へ戻る

#### Scenario: URL を開き直すと同じ画面が出る

- **WHEN** 元帳・補助元帳・設定セクションを開いた状態の URL を開き直す
- **THEN** 同じ画面が復元される

#### Scenario: 解釈できないハッシュはホームへ倒す

- **WHEN** 解釈できないハッシュを含む URL を開く
- **THEN** ホームを表示する（エラー画面にしない）

#### Scenario: 旧形式 `?tab=` を片方向で正規化する

- **WHEN** 旧形式のディープリンク `?tab=<tab>` で開く
- **THEN** `#<tab>` へ正規化して該当画面を開き、以後のリンク生成では旧形式を使わない

### Requirement: ホームのダッシュボード

システムはホーム画面で当期の状況を要約表示する SHALL。

#### Scenario: KPI と月次収支を表示する

- **WHEN** 利用者がホームを開く
- **THEN** 現預金残高・売上・経費・所得などの KPI と、月次収支のグラフを表示する

#### Scenario: 納税予測と what-if を表示する

- **WHEN** ホームの納税予測カードで追加経費・追加所得控除を入力する
- **THEN** `GET /api/tax-forecast` の what-if 結果と基準予測との差を表示する
- **AND** 参考値である旨の免責を常に表示する

#### Scenario: 「今やること」を提示する

- **WHEN** 未確定の draft・未設定の会計年度・未登録の開始残高などがある
- **THEN** 対応する画面への導線を伴う作業リストを表示する

### Requirement: 帳簿選択画面

システムは事務所モードの起点として、対象の帳簿（顧問先）を選ぶ画面を提供する SHALL。
アプリを開いた直後に帳簿が黙って開いている状態を作らない。

#### Scenario: 起動直後に帳簿を選ぶ

- **WHEN** モードが `office` でアプリを開く
- **THEN** アクティブな帳簿の一覧を表示し、利用者が選ぶまで業務画面へ進まない

#### Scenario: 前回開いた帳簿を示す

- **WHEN** 帳簿選択画面を表示する
- **THEN** 前回開いた帳簿をハイライトする
- **AND** ハイライトだけでは開かない（選択の操作を必ず経る）

#### Scenario: 帳簿が1冊でも選択を経る

- **WHEN** モードが `office` でアクティブな帳簿が1冊しか無い
- **THEN** それでも帳簿選択画面を表示する（「必ず選んでから触る」規律を崩さない）

#### Scenario: 帳簿選択へ戻る

- **WHEN** 業務画面で「帳簿を切り替える」を選ぶ
- **THEN** 開いている帳簿を閉じて帳簿選択画面へ戻り、前の帳簿の画面状態（選択年度・絞り込み・開いている元帳）を持ち越さない
- **AND** 帳簿を閉じる操作と切り替える操作は同一の導線とする（閉じた先が選択画面なので、別々の出口を設けない）

### Requirement: 初回セットアップ導線

システムは未設定の前提を順に埋めさせてから業務画面へ進ませる SHALL。
順序は アプリモード → （事務所モードなら）帳簿の選択 → 会計年度 とする。

#### Scenario: モードを選ばせる

- **WHEN** アプリモードが未設定の状態でアプリを開く
- **THEN** 「自分の帳簿をつける」「複数の事業者の帳簿を預かる」のように行為で選べる選択画面を表示する
- **AND** あとから設定画面で変更できる旨を示す

#### Scenario: 推奨年度を提示して作成する

- **WHEN** 対象の帳簿が定まった状態で、その帳簿に open 年度が無い
- **THEN** 推奨年度（`GET /api/fiscal-years/suggested`）を初期値としたセットアップ画面を表示し、作成後に通常画面へ進む

#### Scenario: 帳簿ごとに年度ゲートを通す

- **WHEN** モードが `office` で、年度が未作成の帳簿を開く
- **THEN** その帳簿について年度セットアップを表示する（帳簿ごとに独立して判定する）

### Requirement: AI 連携の疎通案内

システムはホーム画面のセットアップ案内で、AI 連携（[[mcp-server]]）の疎通状態を提示する SHALL。
取込の分類を AI に委ねる導線を持つ以上、その相手と繋がっているかはセットアップの一部である。

**導入の有無を断定してはならない。** アプリはクライアントが導入されているかを判別できないため、
提示できるのは観測できた到達の有無と、表明された版が同梱版と一致するかだけである。
「導入されていない」ではなく「まだ確認できていない」として書く。

案内は帳簿の成立に関わる項目（事業者設定・開始残高・連携サービス）の後に置く。
これらが欠けると帳簿が作れないのに対し、AI 連携は欠けても人が画面で分類できるためである。

#### Scenario: 到達を観測していないことを案内する

- **WHEN** MCP クライアントの到達が一度も記録されていない状態でホームを開く
- **THEN** 連携がまだ確認できていない旨と、一度試してみる導線を提示する
- **AND** クライアントが導入されていないとは書かない

#### Scenario: 一致しない版が使われていることを案内する

- **WHEN** 最後に観測された版が同梱版と一致しない状態でホームを開く
- **THEN** 一致しない版が使われた事実を、観測した時点とともに提示する
- **AND** 設定画面の書き出し導線へ誘導する

#### Scenario: 疎通が確認できていれば案内しない

- **WHEN** 同梱版と一致するクライアントの到達が記録されている状態でホームを開く
- **THEN** AI 連携についての案内を表示しない

#### Scenario: 案内は過去の観測として書く

- **WHEN** 到達の記録を案内に用いる
- **THEN** 現在の状態を断定せず、いつ観測したものかが分かる形で提示する

### Requirement: 例外ベースの取込レビュー

システムは取込 draft を確信度・期間・摘要で絞り込み、一括確定と個別精査を分けて行える UI を提供する SHALL。

#### Scenario: 確信度で絞って一括確定する

- **WHEN** 確信度 high の draft を絞り込んで選択し一括確定する
- **THEN** `POST /api/entries/confirm-batch` を呼び、成功件数と失敗件数を表示する

#### Scenario: AI の根拠を確認する

- **WHEN** draft 一覧を表示する
- **THEN** 各件の由来（提案理由・確信度・証跡参照）を表示し、確定前に人が判断できるようにする

#### Scenario: 明細の科目を修正して確定する

- **WHEN** 提案科目を修正して確定する
- **THEN** 修正後の科目で仕訳が確定し、学習に反映される

### Requirement: 取込明細の年スコープ

システムは取込明細の一覧を**既定で開いている会計年度に閉じて**表示する SHALL。過年度は利用者の
明示操作でのみ表示し、表示していない件数は常に画面上に示す。過年度の行では、サーバが拒否する操作
（復帰＝再仕訳）を提供しない。

一覧は作業キューであり、当年度に処理すべき明細を見る場所である。過年度の行が同じ並びに混ざると、
どこまでが当期の仕事なのかが分からなくなる。一方で過年度の行は証跡として残り続けるため、
「見えない」ことと「無い」ことは区別できなければならない。

#### Scenario: 既定では当年度だけを見せる

- **WHEN** 利用者が取込明細を開く
- **THEN** 開いている会計年度に属する明細だけを表示する

#### Scenario: 過年度を明示操作で出す

- **WHEN** 利用者が過年度を含める操作を行う
- **THEN** すべての年度の明細を表示し、過年度の行は年付きの日付で当年度と区別できる

#### Scenario: 隠した件数を示す

- **WHEN** 会計年度の絞り込みによって表示されない明細がある
- **THEN** その件数を画面上に示し、過年度を表示する手段を併せて提示する

#### Scenario: 過年度の行では復帰を提供しない

- **WHEN** 過年度を表示した状態で、開いている会計年度の範囲外の行を見る
- **THEN** 復帰の操作を実行できない状態で示し、その理由を伝える

### Requirement: 繰越前の未処理明細の提示

システムは年度繰越の確認前に、当期に未処理のまま残っている取込明細の件数を利用者に示す SHALL。
これは警告であり、繰越の操作を塞がない。

#### Scenario: 繰越の確認前に件数を出す

- **WHEN** 利用者が年度繰越の実行を選ぶ
- **THEN** 当期に未処理（未仕訳・除外）で残っている取込明細の件数を、確定の前に表示する

#### Scenario: 未処理があっても繰越を選べる

- **WHEN** 未処理の取込明細が残った状態で確認する
- **THEN** 繰越の実行操作は無効化されず、利用者の判断で実行できる

### Requirement: 一覧行の表記規則

システムは一覧の各行に、**行ごとに変わる値だけ**を表示する SHALL。全行で同じ値は行から外し、
見出しなど1箇所にまとめて示すか、表示しない。

行の幅は有限であり、全行同一の値がそれを消費すると、行ごとに変わる値（摘要など）が押し出されて
折り返す。折り返しの位置は内容の長さで動くため、行ごとに揃わず、目で追える列が消える。
削るべきは情報ではなく**重複**である。

この規則は表示の配置にのみ及ぶ。「例外ベースの取込レビュー」が求める提案理由・確信度・証跡参照は、
いずれも引き続き画面上で確認できなければならない。

#### Scenario: 会計年度が同じ行では年を表示しない

- **WHEN** 一覧の行の日付が、開いている会計年度に属する
- **THEN** 年を省いた月日で表示する

#### Scenario: 会計年度が異なる行は年付きで表示する

- **WHEN** 一覧の行の日付が、開いている会計年度に属さない
- **THEN** 年を含めて表示し、当年度の行と区別できるようにする

#### Scenario: 見出しに出ている値を行に重複させない

- **WHEN** ある値が一覧の見出しやサイドバーで既に示されており、かつ一覧のすべての行で同じである
- **THEN** その値を各行に繰り返さない

#### Scenario: 摘要を切り詰めても全文を失わない

- **WHEN** 摘要が列の幅に収まらない
- **THEN** 表示は切り詰めるが、全文をその場で確認できる手段を残す

### Requirement: 一覧行の折り返し

システムは一覧の行を、**既定のウィンドウサイズで意図しない折り返しが起きない**密度で構成する SHALL。
1行に収まらない情報を持つ行は、内容の長さで折り返し位置が動く形ではなく、**全行で同じ位置に
現れる従属行**として構成する。

意図しない折り返しは、行ごとに違う位置で起きるため列が崩れる。意図した従属行は、行ごとに同じ
位置で始まるため列が保たれる。同じ2行でも読めるかどうかが変わる。

#### Scenario: 既定のウィンドウで折り返さない

- **WHEN** 既定のウィンドウサイズで取込 draft 一覧・取込明細を表示する
- **THEN** どの行も意図しない折り返しを起こさない

#### Scenario: 従属行は行ごとに同じ位置に現れる

- **WHEN** 行が従属行（分類の根拠・例外的な指定など）を伴う
- **THEN** その従属行は主行と区別でき、かつすべての行で同じ位置から始まる

#### Scenario: 表の行の高さが一定である

- **WHEN** 表形式の一覧を表示する
- **THEN** 内容の長短によって行の高さが変わらない

### Requirement: 設定画面

システムは各種設定として、アプリモード・マスタ管理・事業者設定・帳簿管理・データ管理・
AI クライアント連携を提供する SHALL。

#### Scenario: アプリモードを変更する

- **WHEN** 設定画面でアプリモードを変更する
- **THEN** 変更後の起動導線と UI の露出範囲を説明したうえで保存する
- **AND** `office` から `personal` への変更がアクティブ2冊以上で拒否された場合は、帳簿管理への導線を示す

#### Scenario: マスタを管理する

- **WHEN** 設定画面のマスタタブを開く
- **THEN** 勘定科目/補助科目・取引先・部門・品目・タグ・自動仕訳ルール・取込口座・取込フォーマットを閲覧・編集できる

#### Scenario: 帳簿を管理する

- **WHEN** 帳簿のパネルを開く
- **THEN** 帳簿の一覧・作成・改名・アーカイブ・復帰ができる
- **AND** アーカイブ済みの帳簿を明示操作で表示できる
- **AND** 削除の導線は提供しない

#### Scenario: アーカイブの意味を示す

- **WHEN** 帳簿をアーカイブしようとする
- **THEN** データは削除されず一覧から下がるだけであること、いつでも復帰できることを示してから実行する

#### Scenario: 全データをエクスポートする

- **WHEN** データ管理から「エクスポート」を実行する
- **THEN** 現在対象になっている帳簿の zip をダウンロードする

#### Scenario: AI クライアントとの連携を設定する

- **WHEN** 設定画面から AI クライアント連携の導線を実行する
- **THEN** 導入用のバンドル（[[mcp-server]]）を書き出し、その場所を利用者に提示する
- **AND** 導入の手順と、連携後にできること・できないこと（承認は本アプリで行う）を示す

#### Scenario: 連携できているかを確かめられる

- **WHEN** 連携の導線を開く
- **THEN** 連携がまだ行われていないのか、既に設定済みなのかが区別できる形で示される

### Requirement: エラーの提示

システムは API エラーを成功と区別できる表示で提示する SHALL。

#### Scenario: 失敗を成功色で見せない

- **WHEN** API が 4xx/5xx を返す
- **THEN** エラーとして識別できる表示でメッセージを提示し、成功時の表示と混同させない

### Requirement: 取込の開始と進行の提示

システムは連携サービスの取込をアプリの画面から開始でき、**進行と結果を人が追える形**で提示する SHALL。
進行中であることが分からないまま待たせてはならない。

#### Scenario: 連携サービスから取込を開始する

- **WHEN** 連携サービスの一覧から取込を開始する
- **THEN** 巡回のウィンドウが開き、画面上に進行中であることが示される

#### Scenario: ログイン待ちであることが分かる

- **WHEN** 巡回がログインまたは2要素認証の入力を待っている
- **THEN** 何を待っているのかと、どの画面に入力すればよいのかが示される

#### Scenario: 結果の内訳を示す

- **WHEN** 取込が完了する
- **THEN** 受理・重複・期間外除外・未確定・警告の件数を示し、draft の確認へ進む導線を出す

#### Scenario: 失敗したことと次にできることを示す

- **WHEN** 巡回が失敗する
- **THEN** どの段階で失敗したかを示し、再試行の導線を出す（原因不明のまま黙って終わらない）

#### Scenario: 進行中の取込を中断できる

- **WHEN** 進行中の取込を中断する
- **THEN** 巡回が止まり、そこまでの分が投入されなかったことが示される

### Requirement: 分類方針の編集

システムは科目の当て方の方針を画面から編集できる SHALL。方針は分類を委ねる相手へ渡され、
判断の基準になる（[[acquisition]]）。方針で会計上の検証が変わらないことを利用者へ示す。

#### Scenario: 方針を編集して保存する

- **WHEN** 設定画面で分類方針を書き換えて保存する
- **THEN** 以後の分類でその方針が使われることが示される

#### Scenario: 既定へ戻せる

- **WHEN** 編集した方針を取り消す
- **THEN** 同梱の既定へ戻り、そのことが示される

#### Scenario: 方針の効く範囲を示す

- **WHEN** 分類方針の編集画面を開く
- **THEN** これが分類の判断にのみ効き、期間や二重計上の検証は変わらないことを示す

### Requirement: 確定申告画面

システムは「決算・申告」グループに確定申告画面を提供し、申告前チェック → 入力指示書 →
提出（手動または AI 転記）→ 完了記録の流れを一つの画面で辿れるようにする SHALL。
AI 連携（[[mcp-server]]）が無くても、チェック・指示書の手動転記・完了記録は画面だけで完結する。
「提出可能」の宣言は行わない（[[filing]]）。

#### Scenario: 申告前チェックの結果を示す

- **WHEN** 確定申告画面を開く
- **THEN** [[filing]] の precheck 結果を不備と注意に区分して表示し、各項目に該当画面への導線を付す
- **AND** 不備が見つからなかった場合も「提出可能」とは表示しない

#### Scenario: 入力指示書を閲覧・コピーできる

- **WHEN** 入力指示書を開く
- **THEN** 作成コーナーの画面順に転記項目（画面名・欄ラベル・転記値）と検算用税額を表示し、
  各転記値を個別にコピーできる（AI なしでも手動転記が完結する）

#### Scenario: AI 転記の案内を疎通状態に合わせる

- **WHEN** 提出方法の案内を表示する
- **THEN** MCP クライアントの到達が観測済みなら「確定申告の転記」の定型手順から始める手順を、
  未観測なら連携セットアップへの導線を示す
- **AND** 導入の有無は断定しない（AI 連携の疎通案内と同じ規約）

#### Scenario: 完了を記録し控えを残す

- **WHEN** 提出後に年分・税目・提出方法・提出日・受付番号を入力し、控え PDF を添付する
- **THEN** [[filing]] の完了記録として保存され、画面の一覧に記録と添付が表示される

#### Scenario: 記録済みの年分を示す

- **WHEN** 完了記録が存在する年分の確定申告画面を開く
- **THEN** 提出済みの記録（税目・提出日・受付番号・控え）が確認でき、再提出の記録も追加できる
