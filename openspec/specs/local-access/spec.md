# local-access Specification

## Purpose

ローカルアプリのアクセス境界を定める。認証を持たない代わりに、**到達性そのものを防壁**とする。
到達性の絞り方は経路により2通りある。デスクトップアプリでは UI をアプリ内部で配信して TCP を
一切開かず、外部プロセス向けにはアプリ起動中だけ存在するローカルソケットを開く。
開発時は `127.0.0.1` 限定の TCP 待ち受けを用いる。いずれの場合も外部公開へ切り替える手段は持たない。
アプリの起動・終了そのものの規約は [[desktop-app]]、どの帳簿を対象にするかの解決は [[books]] が担う。
（[docs/architecture.md] §5/§12.0・[docs/PRD.md] F-AUTH）

## Requirements

### Requirement: ループバック限定の待ち受け

システムは TCP で待ち受ける場合、その待ち受けを `127.0.0.1` に固定し、同一マシン以外からの
到達を不可能にする SHALL。設定で外部公開へ切り替える手段を提供してはならない。

デスクトップアプリとして動作する場合、UI 経路は TCP を用いずアプリ内部で配信され
（[[desktop-app]]）、TCP の待ち受けは開発時にのみ存在する。本要件は「TCP を開くならば
必ずループバック限定であり、それを設定で覆せない」という不変条件であって、
TCP の待ち受けが存在することを要求するものではない。

#### Scenario: ループバックからのリクエストを受け付ける

- **WHEN** TCP で待ち受けている状態で、同一マシンのプロセスが `http://127.0.0.1:<port>/api/*` を呼ぶ
- **THEN** 認証情報を要求せずに処理する

#### Scenario: 同一 LAN の他ホストから到達できない

- **WHEN** 同一 LAN の別ホストがサーバの LAN アドレス宛にリクエストする
- **THEN** ソケットレベルで接続が確立せず、いかなる会計データも返さない

#### Scenario: 外部公開へ切り替える設定を持たない

- **WHEN** 環境変数や設定ファイルでバインドアドレスを変更しようとする
- **THEN** そのような設定項目は存在せず、TCP で待ち受ける場合の待ち受けは常に `127.0.0.1` である

#### Scenario: パッケージ版は TCP を開かない

- **WHEN** 配布されたデスクトップアプリが起動している
- **THEN** Kanean に属する TCP の待ち受けポートは存在しない

### Requirement: シード追加への自己修復

システムは data plane を開くたびに冪等なシード適用を行い、後から追加された標準シードへ追いつかせる SHALL。

#### Scenario: 開くたびに不足シードを補う

- **WHEN** `DbRouter.bookDb()` が既存の data plane を開く
- **THEN** 不足している `is_system` シードを冪等に投入する
- **AND** 利用者側の操作を一切要求しない

### Requirement: 取込スキルの呼び出し境界

システムは `/skill` 配下のルートを、**ローカル到達性のみ**を条件として受け付ける SHALL。
トークンその他の認証情報を要求してはならない。対象帳簿の解決は [[books]] の規約に従う。

ローカル到達性の実体は経路により2通りある。開発時は `127.0.0.1` への TCP 接続、
デスクトップアプリではアプリ起動中だけ存在するローカルソケットへの接続である。
いずれの経路でも受け付ける振る舞い（認証なし・帳簿解決・ボディ上限）は同一とする。

ローカルソケットが受け付ける範囲は `/skill` 配下に限らず、**UI が用いるのと同じ業務 API 全体**とする。
到達性が唯一の境界である以上、経路ごとに露出するルートを変えても防壁にはならないためである。
[[mcp-server]] のブリッジもこの境界の内側に位置づけ、同じ条件（認証なし・ローカル到達のみ）で受け付ける。
**どの操作を外部クライアントへ露出するかはこの境界とは別の問題**であり、露出範囲は [[mcp-server]] が定める。

#### Scenario: ローカルのスキルが認証なしで呼ぶ

- **WHEN** 同一マシンで動作する取込スキルが `/skill/*` を呼ぶ
- **THEN** 解決した帳簿の data plane に対して処理し、認証情報を要求しない

#### Scenario: ローカル連携クライアントが業務 API を呼ぶ

- **WHEN** 同一マシンで動作する MCP ブリッジがローカルソケット経由で `/api/*` を呼ぶ
- **THEN** UI から同じ API を呼んだ場合と同じ結果を返し、認証情報を要求しない

#### Scenario: 経路によらず同一の振る舞いになる

- **WHEN** 同一のリクエストを TCP 経路とローカルソケット経路のそれぞれで送る
- **THEN** ステータス・応答本文・帳簿解決の結果が一致する

#### Scenario: 過大なリクエストを遮断する

- **WHEN** 5MB を超えるリクエストボディが `/skill/*` に到達する
- **THEN** 413 を返す

### Requirement: アプリ寿命に縛られたローカルソケット

システムはローカル連携（取込スキル・将来の MCP）の受け口として、アプリの起動中にのみ存在する
ローカルソケットを提供する SHALL。ソケットはポート番号を持たず、その存在自体がアプリの
起動状態を表す。アプリの終了後に受け口を残してはならない。

#### Scenario: 起動でソケットが現れる

- **WHEN** デスクトップアプリが起動する
- **THEN** 既定の位置にローカルソケットが作られ、同一マシンのクライアントから `/skill/*` を呼べる

#### Scenario: 終了でソケットが消える

- **WHEN** デスクトップアプリを終了する
- **THEN** ソケットは削除され、以後その経路から会計データへ到達できない

#### Scenario: 起動していないことを検知できる

- **WHEN** アプリが起動していない状態でローカル連携クライアントが接続を試みる
- **THEN** 接続は失敗し、クライアントは「アプリが起動していない」と判別できる

#### Scenario: 異常終了しても次回起動を妨げない

- **WHEN** 前回のプロセスが異常終了してソケットファイルが残っている状態で起動する
- **THEN** 残存ソケットを掃除して正常に待ち受けを開始する
